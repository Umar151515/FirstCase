# Сервер FirstCase на Windows

Одна рабочая копия Git, один файл управления: `server.cmd` в корне проекта.
Обычный запуск и обновление не требуют PowerShell от администратора.

| Команда | Что делает |
| --- | --- |
| `server.cmd` или `server.cmd start` | Запускает Docker Desktop при необходимости и готовые контейнеры, проверяет API и категории, включает Tailscale Funnel. |
| `server.cmd update` | Получает `main` из GitHub, проверяет код и тесты, собирает образы, сохраняет резервную копию, обновляет сервер. |
| `server.cmd status` | Показывает контейнеры, установленный коммит, проверку API и справочника направлений. |
| `server.cmd logs` | Показывает последние журналы и новые сообщения; Ctrl+C завершает просмотр. |
| `server.cmd restart` | Перезапускает приложение с сохранением данных. |
| `server.cmd backup` | Сохраняет согласованную копию БД, загруженных файлов и конфигурации. |
| `server.cmd stop` | Останавливает контейнеры с сохранением данных. |

В PowerShell добавьте ` .\` перед именем: ` .\server.cmd update`.

## Обновление после коммита с другого ноутбука

1. На рабочем ноутбуке завершите изменения, сделайте коммит и отправьте его: `git push origin main`.
2. На обоих устройствах включите Tailscale с тем же аккаунтом. С рабочего ноутбука подключитесь по SSH с ранее выданным приватным ключом:

   ```text
   ssh -i firstcase_ed25519 admin@desktop-lmn0u13.taila01b06.ts.net
   ```

3. В SSH-сессии перейдите в рабочую копию сервера и запустите обновление:

   ```powershell
   Set-Location 'C:\Users\admin\Documents\Codex\2026-10-19\x20\outputs\FirstCase'
   .\server.cmd update
   ```

Дождитесь `Updated successfully: <коммит>`. `server.cmd status` показывает установленную версию.
Если этот коммит уже работает, повторная команда проверит сервер без повторной сборки.

Обновление использует только fast-forward: незакоммиченные изменения, другая ветка или
расхождение истории останавливают его без перезаписи исходников. Исправления вносите
в Git и отправляйте в `main`; не редактируйте код на сервере между обновлениями.
При ошибке тестов работающие контейнеры остаются прежними. При неудачном переключении
возвращаются предыдущие образы. Новые миграции БД автоматически не откатываются;
перед каждым переключением сохраняется резервная копия.

## Где что находится

- `backend/`, `bot/`, `frontend/`, `shared/` — исходники.
- `scripts/`, `alembic/` — серверные команды и миграции.
- `ops/windows/` — управление Windows-сервером; `ops/compose.test.yml` — изолированные проверки.
- `.env.production` — локальные секреты, исключённые из Git и Docker build context.
- `.server/logs/` — журналы команд; последняя ошибка в `last-error.txt`.
- `.server/deployment.json` — успешно установленный коммит.
- `.server/backups/` — резервные копии, включая конфигурацию с секретами; доступ ограничен владельцем и SYSTEM.
- `.server/history/` — сохранённые старые установочные скрипты и заметки этого ноутбука.

`.server/` целиком исключён из Git и Docker build context. БД и загрузки хранятся
в прежних Docker volumes проекта `firstcase-production`. Команды управления не удаляют volumes.
Копии из `.server/backups/` периодически переносите на отдельный носитель.

## Запуск после перезагрузки

Tailscale и OpenSSH работают как службы. Docker Desktop и приложение запускаются
после входа `admin` в Windows через запись автозапуска FirstCaseServer.
Для ручного запуска достаточно двойного щелчка по `server.cmd`.
На питании от розетки сон и действие закрытия крышки отключены при первоначальной настройке.
Ноутбук должен оставаться включённым, подключённым к интернету и иметь вентиляцию.

## Новая установка

Установите Git for Windows, Docker Desktop с Linux containers и Tailscale.
Клонируйте репозиторий, создайте `.env.production` по production-разделу README,
войдите в Tailscale и разрешите Funnel. Запустите `server.cmd update` для первой сборки.
Production автоматически создаёт необходимые направления без демонстрационных пользователей и задач.

`ops/windows/Setup-Access.ps1` — отдельная первоначальная установка OpenSSH и настройка
питания с правами администратора. Передайте `-PublicKey` с путём к своему публичному
ключу; для локальной проверки входа приватный ключ должен лежать рядом без расширения `.pub`.
При отсутствии Tailscale также передайте `-Installer` с официальным подписанным MSI.
На уже настроенном ноутбуке повторно выполнять эту установку при обновлениях не требуется.

## Проверки разработки

```powershell
docker build --target verify -f frontend/Dockerfile -t firstcase-frontend-verified .
docker compose -p firstcase-tests -f ops/compose.test.yml up -d --wait postgres
docker compose -p firstcase-tests -f ops/compose.test.yml run --rm --build backend
docker compose -p firstcase-tests -f ops/compose.test.yml down
```

Тестовая БД находится в отдельном проекте и временной файловой системе, без публичного
порта и доступа к production volumes. Проверки включают заполнение категорий,
Telegram-авторизацию и публикацию задачи, повторную загрузку справочника в интерфейсе.
